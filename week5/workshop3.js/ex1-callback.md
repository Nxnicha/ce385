ส่วนที่ 1 — สร้างข้อมูลตั้งต้น
จำลองข้อมูลนักศึกษาไว้ในรูปแบบของ Array of Objects จำนวน 4 คน โดยเก็บในตัวแปร `const` ตามข้อกำหนด ข้อมูลแต่ละคนประกอบด้วย `id`, `name`, `major`, และ `score`

#### ส่วนที่ 2 — ฟังก์ชัน `fetchStudentById(id, callback)`
การเขียนฟังก์ชันนี้เป็นไปตามธรรมเนียม Error-first (อาร์กิวเมนต์ตัวแรกของ callback คือ error เสมอ):
1. **Validate Input:** ตรวจสอบก่อนว่า `id` เป็น String และไม่เป็นค่าว่างหรือไม่ ถ้าไม่ใช่ ให้ `return callback(new Error(...))` ออกไปทันที
2. **ค้นหาข้อมูล:** ใช้เมธอด `Array.prototype.find()` ค้นหา `student` ที่มี `id` ตรงกับที่ระบุ
3. **กรณีไม่พบ (Error):** ถ้าตัวแปร `student` เป็น `undefined` ให้ `return callback(new Error(...))` เพื่อแจ้งว่าไม่พบรหัส
4. **กรณีพบข้อมูล (Success):** จำลองความล่าช้า 300ms ด้วย `setTimeout` จากนั้นเรียก `callback(null, { ...student })` 
   - กำหนดอาร์กิวเมนต์แรกเป็น `null` เพื่อระบุว่าไม่เกิดข้อผิดพลาด
   - ใช้ Spread Syntax `{ ...student }` ในการสร้าง object ใหม่ เพื่อ **คืนค่าเป็นสำเนาเสมอ** ป้องกันผลกระทบต่อเนื่อง (Side-effects) กรณีมีการแก้ไขตัวแปรที่รับไป

#### ส่วนที่ 3 — การเรียกใช้งาน (Test Cases)
เรียกใช้ครอบคลุม 3 กรณี และใช้หลักการ **ต้องตรวจ error ก่อนแตะผลลัพธ์เสมอ**:
- **ก) id ที่มีจริง:** (เช่น "65002") ทำงานสำเร็จ ได้ค่า `student.name`
- **ข) id ที่ไม่มี:** (เช่น "99999") เข้าเงื่อนไข `if (error)` และแสดงข้อความเตือน
- **ค) id ผิดรูปแบบ:** (เช่น ส่งตัวเลข `42`) เข้าเงื่อนไข `if (error)` และแสดงข้อความเตือนรหัสไม่ถูกต้อง

###  ตอบคำถาม (ส่วนที่ 4)

**2 ถ้าลืมตรวจ error แล้วอ่าน `.name` ทันที จะเกิดอะไร ใครเห็น error นั้น**
- **เกิดอะไรขึ้น:** ในกรณีที่เกิดข้อผิดพลาด ตัวแปร `student` จะเป็น `undefined` หากไม่ได้ใช้ `if (error)` ดักไว้ก่อน แล้วไปเรียก `student.name` ทันที โปรแกรมจะเกิด **Runtime Error** (`TypeError: Cannot read properties of undefined`) และส่งผลให้โปรแกรมพัง (Crash)
- **ใครเห็น:** Developer จะเห็นผ่านหน้าต่าง Console/Terminal หรือ Log ของเซิร์ฟเวอร์ แต่ถ้าเป็นบน Production ผู้ใช้งานทั่วไป (User) อาจจะเจอระบบล่ม, ค้าง, หรือ Error 500 (Internal Server Error) โดยไม่ทราบสาเหตุ

**1 ทำไมต้อง `return` หลังเรียก `callback(error)`**
- **เหตุผล:** เพื่อหยุดการทำงานของฟังก์ชันทันที (Early Return) หากไม่ใส่ `return` ฟังก์ชันจะยังคงทำงานในบรรทัดต่อๆ ไปจนจบ (เช่น แอบไปรัน `setTimeout` ต่อ) สิ่งที่เกิดขึ้นคือจะมีการเรียก `callback` มากกว่า 1 ครั้งในฟังก์ชันเดียว ซึ่งทำให้การประมวลผลผิดพลาดและเกิดบั๊กตามมา
